## Decisions that override the blueprint

- **Hosting/DB (2026-09-14):** HelioHost deployment uses **PostgreSQL**, not SQLite. The app is **not offline-capable** — always requires connectivity. This overrides Section 30 ("Local-First Architecture") and the SQLite-first framing in Section 32 ("Database Strategy") of the blueprint. Local-first/sync-engine architecture is not the plan.

- **`study_os_overview-v2.pdf` is product/UX vision only, not an infra spec (2026-09-14):** This earlier project doc describes a fully local-first, on-device architecture — Python embedded in the Android app via Chaquopy, LLM inference via a native llama.cpp build on-device, SQLite as the source of truth, offline-capable for everything except web research, and a centralized backend as a later optional addition for accounts/sync. User explicitly confirmed the already-built server+Postgres, always-online architecture (above) is the correct one — **the code is the source of truth, not this document.** The doc's product/UX ideas (single-prompt home screen, quick actions, Study Modes, the block-rendering contract) remain useful references for frontend design, since they map closely onto what's already implemented server-side (the `Block` schema already covers text/equation/interactive_graph/diagram/animation/3d/pdf/source/table); its infrastructure sections (§2, §22, §27, §30, §35 — Chaquopy, on-device llama.cpp, offline-first, SQLite, APK bundling) do not apply and should not inform backend or deployment decisions.

### 2026-09-20 — REDESIGNED + BUILT (backend): hosted pay-as-you-go AI tier, replacing the BYOK auto-provisioning idea

**Critical finding, verified against primary sources, not summaries**: the literal mechanism in the notes — mint a brand-new Anthropic/OpenAI/DeepSeek API key *for* a paying user and hand them the raw credential (auto-filled + emailed) — is exactly what Anthropic's Commercial Terms of Service (`anthropic.com/legal/commercial-terms` §D.4) and its Claude Code legal/compliance page (`code.claude.com/docs/en/legal-and-compliance`) prohibit: *"Customers may not pay for, resell, or intermediate Claude usage on their end users' behalf. Each end user must authenticate with their own Anthropic API key... billed directly to the end user under their own agreement with Anthropic."* OpenAI's business terms similarly prohibit buying/selling/transferring API keys with a third party. DeepSeek's terms require the key holder not share/disclose it to others. All three draw the same line: a company using **its own** key for its own product is fine (the ordinary SaaS-on-API pattern); minting a **new** key **for** an end user and handing over the raw credential is not.

**User's redesign decision** (AskUserQuestion): drop per-user key provisioning entirely. Instead, **Study OS holds its own pooled provider key(s)** under its own agreement with each provider; a user who wants a stronger model than free local Qwen pays Study OS directly for **metered usage** of Study OS's own hosted tier — no raw provider key is ever provisioned for or shown to an individual user. ### 2026-10-07 (later) — FIXED: uploads indexed in the background; Render health-check restarts

After the memory fix deployed, the upload still failed; Render alerted `Get "http://…:10000/api/health": … connection reset by peer`. Root cause: indexing (PDF extraction + embedding) ran **inside the upload request on the event loop** — minutes of CPU on Render's fractional CPU, during which the server answered nothing, including Render's health check, so the instance was restarted mid-upload. **Fix:**

- Embedding (`rag/indexing`, `rag/semantic_search`) runs via `asyncio.to_thread`; `TextEmbedding(threads=1)`.
- App startup (`lifespan`) marks any material still `indexing` as failed ("interrupted by a server restart — upload it again").
- Flutter Sources tab: per-material Indexing…/Ready/Failed badge with the reason, polls every 4 s only while something is indexing, refreshes chunk count when done, snackbar on upload.
- Tests index inline (conftest flag) except the new `test_background_indexing.py`.
